# Registro de supuestos y restricciones

| Metadato | Valor |
|---|---|

## Registro de supuestos

| ID | Descripción | Categoría | Grado de impacto | Estrategia de validación |
|---|---|---|---|---|
| SUP-01 | Se dispondrá de datos representativos de pedidos, vehículos, conductores y ventanas de tiempo. | Operativa | Alto | Revisar muestra inicial, campos obligatorios y consistencia antes del MVP. |
| SUP-02 | Las coordenadas o puntos de referencia permitirán ubicar la mayoría de las entregas. | Técnica | Alto | Geocodificar una muestra y medir porcentaje de ubicaciones válidas. |
| SUP-03 | Operaciones podrá participar en revisiones quincenales. | Operativa | Medio | Acordar calendario y registrar asistencia/decisiones. |
| SUP-04 | Una API de mapas o un servicio abierto ofrecerá trazado suficiente para la demostración. | Técnica | Alto | Ejecutar prueba de factibilidad y mantener proveedor alternativo. |
| SUP-05 | Los parámetros de consumo, emisiones y costos serán estimaciones válidas para comparar alternativas. | Financiera | Medio | Contrastar con datos de la consigna y documentar fuente/fecha. |
| SUP-06 | El equipo contará con conectividad, repositorio GitHub y ambiente de desarrollo durante el periodo académico. | Técnica | Medio | Verificar accesos, ramas, permisos y respaldos en la primera semana. |
| SUP-07 | La flota de prueba puede modelarse con 15 vehículos y restricciones conocidas. | Operativa | Medio | Validar modelo de flota con casos de prueba y escenarios límite. |
| SUP-08 | La información usada en el prototipo podrá anonimizarse sin afectar las pruebas. | Operativa | Alto | Eliminar datos personales y aplicar revisión del conjunto de prueba. |

## Registro de restricciones

| ID | Descripción | Categoría | Severidad | Flexibilidad de negociación |
|---|---|---|---|---|
| RES-01 | El proyecto debe concluir antes del 18/12/2026. | Tiempo | Alta | Baja; solo se negocia priorización interna. |
| RES-02 | El presupuesto referencial no debe superar S/ 6,000. | Costo | Alta | Media; requiere aprobación del patrocinador. |
| RES-03 | Los cinco artefactos de inicio deben residir en `docs/01 Inicio/` con nomenclatura exacta. | Normativa | Alta | Nula. |
| RES-04 | La solución debe ser una plataforma web y mantener trazabilidad en GitHub. | Tecnología | Alta | Baja. |
| RES-05 | El optimizador debe respetar capacidad, ventanas de tiempo y descansos de conductor. | Normativa | Alta | Nula en datos de evaluación. |
| RES-06 | Las rutas deben considerar restricciones vehiculares y la realidad de congestión de Lima. | Normativa | Alta | Baja; se parametriza, no se elimina. |
| RES-07 | El uso de APIs externas estará condicionado por cuotas, claves y disponibilidad. | Tecnología | Media | Media; se permite simulación y proveedor alternativo. |
| RES-08 | Los datos personales de clientes y conductores no deben exponerse en repositorios públicos. | Normativa | Alta | Nula. |

## Seguimiento

El director del proyecto revisará este registro semanalmente y antes de cada hito. Un supuesto invalidado se convertirá en riesgo o solicitud de cambio; una restricción nueva deberá incluir propietario, impacto y decisión documentada.
