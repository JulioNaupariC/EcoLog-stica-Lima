## Reglas codificadas

| ID | Regla de negocio |
|---|---|
| RN-001 | Después de tres intentos fallidos consecutivos, la cuenta se bloquea durante 15 minutos y se registra el evento. |
| RN-002 | Cada operación se autoriza según rol y, para conductores, según asignación de ruta y jornada. |
| RN-003 | La suma de pesos y volúmenes de pedidos de una ruta no puede superar la capacidad registrada del vehículo. |
| RN-004 | Un vehículo no puede ser asignado si está inactivo, averiado o su placa tiene restricción aplicable en el periodo configurado. |
| RN-005 | Un conductor no puede recibir una ruta que exceda ocho horas de conducción o cuatro horas continuas sin un descanso de una hora. |
| RN-006 | Un pedido requiere una ventana con inicio anterior al final y una ubicación mediante coordenadas válidas o punto de referencia verificable. |
| RN-007 | Los pedidos perecederos y express tienen mayor penalización por tardanza que los estándar y económico, según parámetros versionados. |
| RN-008 | Al cancelarse un pedido o reportarse una avería/incidente validado, solo se reoptimiza el conjunto de paradas pendientes. |
| RN-009 | Un pedido que no puede ser asignado debe conservar motivo explícito: capacidad, ventana, ubicación, recurso o restricción vial. |
| RN-010 | Una alerta de riesgo vial no prohíbe automáticamente una vía; aumenta el costo de ruta salvo que el Administrador la configure como bloqueo. |
| RN-011 | El costo de combustible se calcula como kilómetros / rendimiento × precio configurado; el valor inicial de referencia es S/ 17.50 por galón de diésel. |
| RN-012 | El costo de mantenimiento se calcula con el parámetro vigente; el valor inicial de referencia es S/ 1.20 por km. |
| RN-013 | Las emisiones estimadas se calculan con distancia por factor de emisión del vehículo y muestran el factor y fecha usados. |
| RN-014 | La equivalencia de compensación solo se muestra si existe un factor de captura vigente y un proyecto registrado; no es un crédito certificado por defecto. |
| RN-015 | La eliminación física de datos operativos no está permitida desde la aplicación; se aplica desactivación lógica y auditoría. |
| RN-016 | Solo un Administrador autenticado restablece la contraseña de otro usuario existente que no esté inactivo. La temporal vence a las 24 h desde su emisión, se entrega una sola vez y solo se guarda su hash. El Administrador usa cambio de contraseña, no este restablecimiento, para su propia cuenta. |
| RN-017 | El usuario que ingresa con temporal debe cambiarla antes de acceder a funciones operativas. La nueva contraseña requiere la actual válida, mínimo 12 caracteres y ser distinta de la actual. Al completar el cambio la temporal ya no es válida; no puede reutilizarse para otro ciclo de recuperación. |
| RN-018 | El restablecimiento revoca todas las sesiones previas del objetivo; el cambio de contraseña revoca las demás y conserva la actual. Ambas acciones quedan auditadas con actor, objetivo y conteo de sesiones, sin contraseñas ni hashes; un fallo de la transacción no confirma el cambio. |
| RN-019 | Solo el Conductor registra una incidencia a su nombre, con tipo (TRAFICO, AVERIA, ACCIDENTE, CLIMA, SEGURIDAD u OTRO), severidad (BAJA, MEDIA o ALTA), ubicación válida y hora obligatorios; observación opcional de hasta 500 puntos de código Unicode. Se inicia en PENDIENTE_VALIDACION; el cliente no elige reportante ni estado. Puede reportarse sin ruta/parada; si incluye parada se verifica propiedad y la jornada sigue siendo obligación pendiente de ECL-82. El registro no valida, reoptimiza ni bloquea una vía automáticamente. |
| RN-020 | Los datos incompletos conservan borrador local e indican faltantes. Sin red, un reporte completo se conserva en cola del conductor con identificador de operación estable y se sincroniza al volver la red. La clave idempotente es conductor + operation_id: mismo contenido equivalente devuelve el acuse original sin duplicar; contenido distinto recibe conflicto sin sobrescribir; ninguna cuenta recupera el reporte ajeno. |
| RN-021 | La hora de incidencia incluye zona u offset y se compara como instante UTC: se admite hasta 5 minutos hacia el futuro inclusive respecto del reloj de servidor en el primer envío, sin antigüedad máxima por la cola offline. El reenvío ya registrado se resuelve idempotentemente antes de revalidar el contexto cambiante. Los errores identifican campos sin reflejar sus valores. |
| RN-022 | Solo Administrador y Operador consultan el listado operativo de incidencias pendientes; se pagina y ordena por ocurrida_en descendente e incidencia_id ascendente en empate, con 20 elementos por defecto y máximo 100. Del conductor solo se incluye ID y nombre, sin DNI, teléfono ni licencia. Este alcance no revoca otras capacidades de la matriz global ni crea sus proyecciones. |

## Gestión de cambios

Los precios, factores, zonas y restricciones se almacenan con vigencia, fuente y aprobador. Un cambio no modifica resultados históricos: cada optimización conserva la versión de parámetros usada.
